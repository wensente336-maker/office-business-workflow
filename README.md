# 启衡办公经营工作台（本地教学版）

该网页将老板经营看板、销售、财务、员工日报和部门审核页面连接到同一个 PostgreSQL 业务库 `office_demo_ready`。示例版默认免登录：打开页面即可查看或填报，各页面小字提示“此为示例版已去掉登录账号，真实场景会设置账号权限”。老板看板通过服务端 API 读取最新业务事实；不会把订单直接算作收入。现有 12 周资料和新增演示链路均为虚构教学样本。应用仅绑定 `127.0.0.1`，未部署到公网或手机可访问的服务器。

## 本机启动

依赖：PostgreSQL 16，以及上级目录 `.venv` 中的 `psycopg`。首次使用：

```sh
mkdir -p /private/tmp/office-biz-workflow-pg
/opt/homebrew/opt/postgresql@16/bin/initdb -D './pg-data' --auth-local=trust --encoding=UTF8 --locale=C
/opt/homebrew/opt/postgresql@16/bin/pg_ctl -D './pg-data' -l './pg-server.log' -o '-c listen_addresses= -k /private/tmp/office-biz-workflow-pg -p 55433' start
../.venv/bin/python setup.py --create-db
../.venv/bin/python setup.py --demo-accounts
OFFICE_DB_USER=office_demo_writer ../.venv/bin/python server.py --port 18766
```

打开 <http://127.0.0.1:18766/>。`--demo-accounts` 仅在首次初始化时创建数据库内部演示身份，供审计记录关联业务人员；网页不会展示或要求输入这些账号与密码。首次数据库初始化只运行一次；后续启动 PostgreSQL 与 `server.py` 即可。

独立页面地址：老板看板 <http://127.0.0.1:18766/owner>；销售 <http://127.0.0.1:18766/sales>；财务 <http://127.0.0.1:18766/finance>；员工日报 <http://127.0.0.1:18766/work>；部门审核 <http://127.0.0.1:18766/review>。各地址直接打开，无登录步骤；老板看板左侧列出四个填报入口。管理员账号配置页面不在示例版展示。

老板看板的「员工与部门 → 员工日报概况」可逐人展开所选周期的工作总结。摘要读取每人的最新有效日报版本和关联事项，按来源指纹缓存；重交、审核或事项变化后会生成新版本。当前未配置模型时明确显示「规则摘要」。如要启用已获授权的 OpenAI 兼容聊天接口，在服务端配置 `EMPLOYEE_SUMMARY_API_URL`（完整的聊天补全接口地址）、`EMPLOYEE_SUMMARY_MODEL`、`EMPLOYEE_SUMMARY_API_KEY`（本地无认证模型可不填），可选 `EMPLOYEE_SUMMARY_TIMEOUT`（秒），再重启网页服务。模型调用只在老板展开员工摘要且缓存未命中时发生；页面显示「AI 汇总」，失败则显示有明确标识的规则摘要。此教学版无登录，正式接入真实员工日报前应恢复权限并确认资料发送范围。

老板看板打开时默认选中 **2026-11-09 至 2026-11-15** 这一期完整教学数据，用户可在「选择数据周期」改选其他周；看板与 AI 助手的「当前所选周期」同步更新。右下角的「AI 助手」是独立的 DeepSeek 数据问答入口。按钮随页面滚动固定在屏幕边缘；手机端位于底部导航上方，对话窗口低于屏幕高度，消息区域独立滚动。可选择当前经营周或全部演示数据，点击三个示例问题或自行输入。服务端先按问题从受限只读业务表取数，周指标由数据库计算，模型只根据本次证据解释；回答附可展开的来源记录。日报仅采用最新有效提交版本；模拟和待核事项保留标记。明细较多时只取相关样本，整体数量以周指标为准。聊天历史只保存在当前网页内存，关闭窗口后可继续，刷新页面后清空。

DeepSeek 凭据保存在本机钥匙串的专用项目中，网页、源码和服务启动配置均不含密钥。模型只在用户主动提问时调用，服务端设有每分钟请求上限；模型不可执行数据库语句或写入业务记录。该入口仍是免登录教学版，任何能够访问本机演示网址的人都能发起付费模型调用；用于真实企业资料前须恢复账号权限，并明确外部模型可接收的数据范围。当前 AI 助手与上方「员工周期总结」是两个独立功能：前者已接 DeepSeek，后者仍显示明确标记的规则摘要。

侧边栏默认收起；点击页面左上角菜单按钮才展开。再次点击按钮、点击页面遮罩或按 Esc 可关闭。手机竖屏仍保留底部直达导航。

经营总览底部新增「经营分析」：按所选经营周读取最新有效已提交日报，以及原资料包 `02业务事项` 对应的 `work.activity_events` 明细，展示部门主要事项、员工明确报告的风险、业务数据待核事项和经营建议；每条可展开查看日报、事项 ID 与来源单据编号。事项中的模拟分派和待人工核验会保留标记，相关金额不会重复计入经营指标。退回且未重交的版本与草稿不参与日报归纳。当前使用本地规则归纳，**尚未接入 AI 摘要模型**；不会凭空补写金额、责任人或风险等级。本周日报覆盖不足时会明确显示「样本不足」，不把空风险栏解释成没有风险。对应只读接口为 `/api/dashboard/analysis?week=YYYY-MM-DD`。

演示链路由 `seed_demo.py` 通过现有岗位接口写入 `office_demo_ready`，包含客户→跟进→商机→报价→订单→回款/费用→日报退回重交审核，记录以“演示链路”标记；重复执行会复用同一日期已有记录。看板“本周演示业务链”可展开查看单据 ID 和关联来源。当前演示链路订单为 12,000 元、回款 4,000 元、发生费用 800 元、实付 500 元；新订单未交付，确认收入不变。

当前这台 Mac 已将 `local.office.business.database.plist` 和 `local.office.business.web.plist` 注册到用户级 `launchd`，数据库和网页服务会在登录后持续运行。工作台须从上面的 **http 地址**打开；直接双击 `public/index.html` 得到的 `file://` 页面无法连接 API。

停止：先终止 `server.py`，再运行 `/opt/homebrew/opt/postgresql@16/bin/pg_ctl -D './pg-data' stop -m fast`。如需在另一台机器启动，改 `OFFICE_DB_SOCKET`、`OFFICE_DB_PORT`、`OFFICE_DB_NAME`、`OFFICE_DB_USER` 环境变量并准备对应库与权限。数据库迁移可重复运行 `../.venv/bin/python setup.py`；该命令需要数据库所有者权限。服务使用单独的 `office_demo_writer` 角色，不使用建库账号。本机教学库通过 Unix 套接字的 trust 认证运行，不应用于多人或公网环境。

## 岗位与数据

| 入口 | 操作 | 对应数据库 |
|---|---|---|
| 销售 | 客户、客户跟进、商机、报价商品明细、由报价生成订单 | `crm.customers`、`crm.followups`、`sales.opportunities`、`sales.quotes/quote_lines`、`sales.orders/order_lines` |
| 财务 | 回款与费用登记，凭证编号防重 | `finance.customer_receipts`、`finance.expenses`、`app.finance_evidence` |
| 员工 | 日报草稿、提交、退回后重交 | `work.daily_reports`、`app.daily_report_versions` |
| 部门负责人 | 本部门日报通过或退回，不能审本人日报 | `app.daily_report_reviews` |
| 经营看板 | 按周读取订单、回款、费用、日报和周指标 | `analytics.v_weekly_kpis` 与业务事实表 |

示例版根据当前页面选用内部演示身份，写入接口仍检查业务字段、关联关系和幂等键，并写入审计表；这只是演示数据归属，**不是访问控制**。任何能访问本机示例网址的人都可打开各岗位页面并修改演示数据。财务凭证号在同一类别下唯一。日报审核保留版本；日报提交率仍按“已提交”计算，审核状态单列。看板可查看历史周与当前周，提交后刷新并切换到业务日期所在周即可看到新数据。实际发生日期须在演示经营周期内且不能晚于当天；预计成交日、报价有效期允许填写未来日期。电脑和手机共用同一网页；桌面宽屏双栏，手机竖屏单栏及底部岗位导航。

## 验证和边界

`../.venv/bin/python integration_test.py` 会在独立的 `office_demo_operational` 测试库中创建带“联调”字样的员工和记录，**不会写入默认演示库 `office_demo_ready`**。它核对客户→跟进→商机→报价→订单→回款/费用→周指标，以及日报审核、权限、幂等和凭证防重。无需运行该脚本才能使用网页。

`browser_acceptance.mjs` 使用本机 Chrome 检查 1440×900 桌面、390×693 和 360×640 手机视口，并核对老板看板左侧入口跳转到销售填报表单。截图保存在 `acceptance/`，其中包含老板看板、销售、财务、日报与部门审核页面。

`browser_form_mapping.mjs` 会拦截浏览器提交，核对各销售、财务、日报与审核表单发送的接口及字段，不向演示数据库写入测试记录。`test_business_chat.py` 与 `test_employee_summary.py` 使用模拟模型响应核对摘要来源、数值与不完整样本提示，不产生模型费用。

这是单机教学实现。前端只能通过本机访问，尚无 TLS、公网部署、企业 SSO、密码找回、真实手机号加密存储、财务更正/冲销、交付确认入口和实机手机验收。已有 `ops.deliveries` 教学数据继续计算历史收入；新订单处于“待交付”，不会自动生成收入。准备真实企业使用前，应确定部署环境、网络访问、数据库凭据与备份策略，补足上述功能并做安全与业务验收。
